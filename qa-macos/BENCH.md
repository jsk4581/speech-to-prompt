# STT 벤치 — 전사 이상 3건의 원인과 통하는 해법

macOS 26.3.1 · Apple M4 · whisper-cpp 1.8.3 (Metal) · `ggml-large-v3-turbo-q8_0`
(맥 기본 티어) · 헬퍼와 동일한 인자 `-l auto -nt -t 5`.

재현: `python3 build-cases.py && WHISPER_MODEL=… ./run-bench.sh`

> **픽스처는 합성 음성입니다.** `fixtures/`의 7개는 사람이 녹음한 것이 아니라 macOS
> `say`로 만든 TTS이고, 언어 혼합 케이스는 한국어 클립과 영어 클립을 무음 1초로 이어
> 붙인 것입니다. 사람은 그렇게 말하지 않으므로 **경계값(0.5초 / 1.6초)은 실제 발화에서
> 다를 수 있습니다.** 4절에 사람 음성으로 확인한 내용을 따로 적었습니다.

---

## 1. 언어가 섞이면 한쪽이 사라진다 (M17)

한국어 한 문장 뒤에 1초 무음을 두고 영어를 붙인 뒤, 영어 길이만 바꿔가며 측정.

| 케이스 | 영어 길이 | 영어가 살아남았나 |
|---|---|---|
| `ctl_ko_ko` | — (한국어 2문장) | 대조군: 둘 다 전사됨. 이어 붙이기 자체는 무해 |
| `mix_word` | 0.5초 (단어 1개) | **살아남음** — `Fuser` 로 정확히 |
| `mix_phrase` | 1.6초 (짧은 구) | **소실** |
| `mix_sentence` | 6.3초 (한 문장) | **소실** |
| `mix_reversed` | 6.3초 (영어가 앞) | **소실** — 순서 무관 |

경계는 **0.5초와 1.6초 사이**입니다. 단어 하나는 통과하고, 구 이상은 사라집니다.
`-l ko`로 고정해도 동일하므로 `auto` 감지만의 문제가 아니라 **파일당 언어를 하나로
고정하는 구조** 자체의 문제입니다.

### 통하는 완화: 초기 프롬프트에 저장소 식별자 주입

```
mix_phrase   기본    → 업로드 핸들러의 … 만들어줘.
mix_phrase  +prompt  → upload handler의 … 만들어줘 useless off instead of fuser
mix_sentence 기본    → 업로드 핸들러의 … 만들어줘.
mix_sentence+prompt  → upload handler의 … add a retry with exponential backoff to
                       the upload handler in the storage module and cover it with
                       a unit test
```

`--prompt "fuser, lsof, /proc, whisper-cli, STP_PORT, …"` 하나로 **사라졌던 영어
구간이 전부 복구**됩니다. STP는 이미 저장소를 읽으므로 식별자 목록은 공짜로 얻습니다.

부작용: 한국어 일부가 영어 표기로 바뀝니다(`업로드 핸들러` → `upload handler`,
`유닛 테스트` → `unit test`). 코딩 프롬프트에서는 오히려 바람직할 수 있지만
(`grill.md`도 "식별자·경로는 영어로 둔다"고 규정), **사용자가 말한 그대로**라는
원칙과는 상충합니다. 판단이 필요한 지점입니다.

### 기본값을 `-l en`으로 바꾸는 안은 탈락

혼합 파일만 보면 `-l en`이 두 언어를 다 살려서 후보로 보였지만, 순수 한국어에
적용하면 무너집니다.

```
ko_pure  -l ko    → 이번 주에 로그인 화면을 다시 만들고 실패했을 때 안내 문구도 …
ko_pure  -l auto  → (동일, 정확)
ko_pure  -l en    → If you fail, you can see the link in the video.
                    If you fail, you can see the link in the video.
                    If you fail, you can see the link in the video.
```

한국어 내용이 통째로 사라지고 무관한 영어 문장이 반복 생성됩니다. 혼합 파일에서도
`업로드` → `Download` 같은 의미 오류가 나왔습니다. **기본값 후보에서 제외.**

## 2. 발화 끝 잡음 꼬리에서 없는 문장이 생긴다 (M14)

```
tail_control        (25.9초, 꼬리 없음)          → 깨끗
tail_over_boundary  (25.9초 + 잡음 → 30.8초)     → 끝에 "감사합니다." 생성
tail_digital_silence(완전한 0 무음 6초)          → 재현 안 됨
```

트리거는 **마지막 30초 윈도우가 거의 비어 있을 때**이고, 완전한 디지털 무음이 아니라
**실제 노이즈 플로어**가 있어야 합니다. 말을 마치고 Stop을 누르기까지의 공백이 정확히
그 조건입니다.

### 옵션별 결과 (각 5회 반복, 결과 동일)

| 옵션 | 결과 |
|---|---|
| `--suppress-nst` | 효과 없음 — 환각 그대로 |
| `--no-fallback` | 효과 없음 |
| `-lpt -0.4` | 효과 없음 |
| `-et 1.8` | 효과 없음 — 디코더 임계값 조정으로는 잡히지 않음 |
| `--vad` (기본 `-vt 0.5`) | **환각 제거, 발화는 그대로** ← 이것만 통함 |
| `--vad -vt 0.3` | 동일 — 임계값을 낮춰도 발화 손실 없음 |

```
기본   → … 유닛 테스트도 같이 만들어줘. 감사합니다.
--vad  → … 유닛 테스트도 같이 만들어줘
```

VAD 모델은 0.9MB입니다(`ggml-silero-v5.1.2.bin`, 아래 링크). 기본 임계값으로 충분하고
정상 발화(`en_sentence`)도 온전히 전사되므로, 임계값 튜닝 없이 켜기만 하면 됩니다.

> 주의: 이 표를 처음 측정할 때 `-lpt -0.4` · `-et 1.8` · `--vad`가 빈 전사를 낸 적이
> 있었으나, 이후 5회 반복에서 한 번도 재현되지 않았습니다. 원인 미상이며 위 표가
> 반복 검증된 값입니다. 다른 기기에서 돌릴 때도 한 번이 아니라 몇 번 돌려보세요.

VAD는 **M17에는 듣지 않습니다** — 언어 선택은 디코딩 단계의 문제라 음성 구간을 잘라도
바뀌지 않습니다.

## 3. 영어 기술 용어의 한글 음차 (M16)

```
ko_with_terms  기본   → 맥퓨저 쓰는데 맥퓨저는 포트 문법을 모르고 슬래시 프록도 없고
ko_with_terms +prompt → … 포트 문법을 모르고 /proc도 없고
```

`슬래시 프록` → `/proc` 이 정확히 복원됩니다. 용어 자체(`퓨저`)가 라틴 문자로
돌아오는지는 프롬프트 구성에 따라 갈렸습니다 — 짧은 식별자 목록에서는 `macfuser`까지
나왔고, 목록이 길어지자 `퓨저`로 남았습니다. M17과 뿌리가 같습니다: 언어가 하나로
고정되면 짧은 영어는 음차되고 긴 영어는 버려집니다.

## 4. 사람 음성으로 확인한 것 (38초, 한국어에 영어 식별자를 섞어 또박또박 발화)

합성 음성의 한계를 메우려고, 개발자가 실제로 말하듯 영어 식별자를 중간중간 섞은 38초를
녹음해 같은 조건으로 돌렸습니다. **화자가 의도적으로 또박또박 발음한 테이크**이고,
`STP_KEEP_AUDIO=1` 로 캡처를 남겼기에 아래 대조가 가능했습니다.

### 또렷하게 발음해도 식별자의 절반 이상이 손상된다

| 말한 것 | 발음 | 기본 전사 | `--prompt` |
|---|---|---|---|
| `lsof` | 엘에스오에프 | **`lsof`** ✓ | `lsof` ✓ |
| `ps` | 피에스 | **`ps`** ✓ | `ps` ✓ |
| `EADDRINUSE` | 어드레스 인 유즈 | **`address in use`** ✓ | `address in use` ✓ |
| `lsof -ti tcp` | 철자 | `lsof-titcp` ~ | `lsof-titcp` ~ |
| `STP_PORT` | 에스티피 포트 | `stp 포트` ~ | `stp 포트` ~ |
| `command line` | 커맨드 라인 | 커맨드 라인 ✗ | **`process command line`** ✓ |
| `/proc` | 슬래시 프록 | 슬래시 프로그 ✗ | **`/proc`** ✓ |
| `fuser` | 퓨저 | 퓨저 ✗ | 퓨저 ✗ |
| `helper` | 헬퍼 | 헬퍼 ✗ | 헬퍼 ✗ |
| `kill` | 킬 | 킬 ✗ | 킬 ✗ |
| `launch.sh` | 런치 점 에스에이치 | **`f.sh`** ✗ | `lsof.sh` ✗ |

핵심은 **발음의 문제가 아니라는 것**입니다. 화자가 또렷하게 말했고 `lsof`·`ps` 처럼
철자로 읽은 것도 있는데, 그중 `launch.sh` 는 `f.sh` 로 뭉개졌습니다. 검색 가능한
식별자로 남아야 할 11개 중 기본 설정에서 온전한 것은 3개뿐입니다.

### `--prompt` 는 부분적이고, 새 오류를 만들 수도 있다

`/proc` 과 `command line` 은 정확히 복원됐습니다. 반면 `fuser`·`helper`·`kill` 은
프롬프트 목록에 넣었는데도 그대로 음차됐고, `launch.sh` 는 `f.sh` 에서 **`lsof.sh` 로
바뀌었습니다** — 프롬프트에 넣은 어휘가 엉뚱한 자리에 끼어든 것입니다.

즉 초기 프롬프트는 기호가 붙은 경로(`/proc`)와 여러 단어짜리 용어(`command line`)에는
확실히 듣지만, 한 단어짜리 식별자에는 듣지 않으며 부작용도 있습니다. 도입한다면 어떤
식별자를 넣을지 선별 규칙이 필요합니다.

### 꼬리 환각은 재발하지 않았고, 그 이유가 확인됐다

이 녹음에서는 `감사합니다` 류의 생성이 없었습니다. 저장된 오디오의 마지막 6초를
0.5초 단위 RMS로 보니 **말이 끝난 뒤 조용한 구간이 1.5초**였고, 마지막 30초 윈도우
(30~38.0초)에 발화가 6.5초 들어 있었습니다 — 2절의 트리거 조건(마지막 윈도우가 거의
비어 있음)이 성립하지 않습니다. 즉 이 결과는 2절과 모순되지 않고, **트리거가 "긴 녹음"이
아니라 "거의 빈 마지막 윈도우"** 라는 것을 뒷받침합니다. 사람 음성으로 재확인하려면
말을 마치고 5초 이상 두고 Stop을 눌러야 합니다.

### 아직 못 본 것

이번 발화에는 긴 영어 구간이 없어서(전부 단어 단위 전환) **1절의 문장 소실은 사람
음성으로 재확인되지 않았습니다.** 짧은 전환이 전부 살아남은 것은 "0.5초 단어는 통과"
관측과 일관됩니다.

## 결론

| 발견 | 통하는 해법 | 비용 |
|---|---|---|
| M17 언어 혼합 소실 | `--prompt` 에 저장소 식별자 주입 | 낮음 — 재료는 이미 있음 |
| M14 꼬리 환각 | `--vad` (기본 임계값) | 중간 — 모델 0.9MB 다운로드 추가 |
| M16 용어 음차 | `--prompt` (부분적) | 낮음 — M17과 동일 조치 |

셋 다 `audio.ts`의 인자 구성 한 곳에서 처리됩니다. 다만 수정의 효과를 측정하려면
**원본 오디오를 남길 수 있어야 합니다**(M15) — 이번에도 실사용 녹음이 이미 삭제된
뒤라 실제 사례를 대조하지 못하고 합성 오디오로 우회했습니다.
